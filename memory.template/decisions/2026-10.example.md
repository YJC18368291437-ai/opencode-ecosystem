# 2026-10 决策记录（示例）

## 2026-10-01 质量优先，分阶段做自动化

- 决策：先做只记录、不干预的 Stage 0，验证数据后再决定是否自动化。
- 原因：自动判断阈值不可靠，误切带来的返工比省下的时间贵。
- 做法：用现成插件做会话切换，自己只写薄层；每步可回滚。
- 未决：真实数据是否支持自动触发。

## 2026-10-02 记忆用纯 Markdown + 索引

- 决策：长期记忆用分层 Markdown，`INDEX.md` 做一行式索引。
- 原因：可读、可 diff、可手改；不引入向量库和常驻服务。
- 未决：索引行数超过 50 行后的归档策略。

## 2026-10-03 检索：广度派子智能体，落盘传路径

- 决策：`AGENTS.md` 增加检索规则，约束 agent 查 Google/GitHub/文档的行为。
- 原因：摘要会丢细节，全文会撑上下文；落盘传路径两头都不伤。
- 边界：只用于子任务独立、只读、需广撒网的场景。
- 未验证：实际省钱幅度；是否导致 agent 过度派子智能体。
