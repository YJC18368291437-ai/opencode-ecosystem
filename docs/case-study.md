# 案例：为什么这样设计

这不是一份「最佳实践」，而是一份在真实约束下做取舍的记录。

## 约束

- 机器内存很小，不能跑本地模型、向量库、常驻服务。
- 月度预算非常小，但不愿意为了省几分钱导致返工。
- 主要用途是长时间、多阶段的 agent 会话，不是一次性问答。
- 需要能解释、能改，不能依赖黑盒。

## 决策 1：记忆用 Markdown + 索引

**候选**：向量库 / SQLite / 纯 Markdown。

**选择**：纯 Markdown + `INDEX.md`。

**原因**：

- 记忆量在几百条以内，语义检索收益不足以抵消复杂度。
- 可读、可 diff、可手改；出错时能直接看到原因。
- `INDEX.md` 注入每个会话，模型知道有哪些记忆，不需要全文注入。

**代价**：需要手动维护索引；超过 50 行要归档。

## 决策 2：交接手动触发，不自动

**候选**：按 token 阈值自动换会话 / 手动 `/switch`。

**选择**：手动，先记录数据（Stage 0）。

**原因**：

- 自动判断阈值不可靠，误切一次返工成本很高。
- 长会话在缓存命中时很便宜；交接的主要收益是质量，不是省钱。
- 手动触发更容易积累「本可以交接 / 不该交接」的真实例子。

**放弃的方案**：全自动交接。曾在 `handoff.json` 里预留阈值和护栏，但没有启用。

## 决策 3：插件只写薄层

**候选**：自己写完整成本系统 / 用现成插件 + 薄层。

**选择**：现成插件 + 约 150 行日志插件。

**原因**：

- TokenScope 已经能按类别拆解会话。
- 缺的只是「按 UTC 峰谷价记录真实成本」和「按 messageID 去重」。
- 薄层容易审计、容易删。

**代价**：依赖第三方插件的版本；升级时要验证 hook 行为。

## 决策 4：检索落盘 + 传路径

**候选**：让子智能体回传全文 / 回传摘要 / 落盘传路径。

**选择**：落盘传路径。

**原因**：

- 摘要会丢细节，全文会撑上下文。
- 结论必须能回查原文；路径是最小可复核单位。
- 多 agent 成本高，只在子任务独立、只读、广撒网时使用。

## 决策 5：学习按天，不按月

**候选**：月计划 / 周计划 / 日级单元。

**选择**：日级单元，最小 10 分钟。

**原因**：

- 固定的大计划容易在中断后全面放弃。
- 最小日只做复习也算完成，降低启动成本。
- 状态机（introduced / mastered）让「今天做到哪」有明确答案。

## 踩过的坑

### 输出截断

- 复核/交接类调用如果 `max_tokens` 太低，会截断，后续解析失败。
- 必须检查 `finish_reason`；不是 `stop` 就当失败。
- 失败只续写一次；仍不完整就保留现场。

### 日志不可靠

- `session.idle` 在 `opencode run` 退出边界上可能来不及写入。
- 改用 `message.updated` + `time.completed`/`finish`，按 `messageID` 去重。
- 汇总脚本也要去重，防插件重启后重复计数。

### 插件 hook 抛错

- 从 hook 抛错会打断 OpenCode。
- 所有 hook 都 try/catch；日志写入失败不能影响主流程。

### macOS 服务环境

- Automator 服务没有登录 shell 的 PATH，`node`、`opencode` 会 `command not found`。
- 服务环境没有 `LANG`，剪贴板中文可能乱码。
- 脚本开头显式设置 PATH 和 `LC_CTYPE`。
- 用 `open -a Terminal <临时 .command>` 比 `osascript do script` 少一个授权弹窗。

## 如果重来

- 先写测试，再改标签规则；纯函数 + 测试让重构便宜很多。
- 日志插件一开始就加去重和轮转，不要等数据脏了再补。
- 文档和代码一起改；否则下个会话只能靠猜。
- 不要为了「自动化」而自动化；先记录，再决定。

## 没做的事

- 不做自动交接 Stage 1–3。
- 不做向量库、本地模型、常驻服务。
- 不做月计划、PDF 自动化。
- 不把完整聊天写进记忆。
