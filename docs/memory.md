# 记忆系统

长期记忆是给下一个会话看的，不是聊天记录。只写以后还会用到、否则会做错或重做的东西。

## 目录与职责

| 内容 | 文件 |
|---|---|
| 用户偏好、语言、禁忌 | `memory/preferences.md` |
| 可复用的踩坑与修复 | `memory/lessons.md` |
| 项目特定事实、命令、架构 | `memory/projects/<project>.md` |
| 影响后续方向的决策 | `memory/decisions/<YYYY-MM>.md` |
| 拿不准 | `memory/inbox.md` |
| 索引 | `memory/INDEX.md` |
| 学习状态 | `memory/learning/`（见 learning.md） |

## 什么时候写

- 用户说「以后都」「记住」「别再」「这个项目的约定是」。
- 做了一个会影响后续方向的决策。
- 踩了一个以后还会踩的坑，并找到了修法。
- 发现用户稳定的偏好（语言、工具、风格、禁忌）。

不要写：一次性的任务细节、临时命令输出、密钥、token、密码、隐私数据。

## 怎么写

1. 先读目标文件，避免重复。
2. 一条一个事实，一行说完；需要解释就缩进一行。
3. 有日期就写日期；有来源会话就写 `source: sess_...`。
4. 写不确定性：`（未验证）`、`（待确认）`。
5. 写完更新 `INDEX.md`：主题 | 文件 | 一句话 | 何时用。
6. `INDEX.md` 不超过 50 行；单个文件不超过 200 行。超了先合并或归档到 `archive/`。

## 索引为什么重要

`INDEX.md` 和 `learning/known.md` 会被注入每个会话。索引太长会挤占上下文，所以它只保留「一行一条」的导航信息，细节留在被引用的文件里。

## 待整理区（inbox）

拿不准放 `inbox.md`。整理时：

1. 读 `inbox.md`。
2. 给每条一个建议目标文件和一句摘要。
3. 用表格给用户确认；**不要静默移动**。
4. 确认后移动、去重、更新 `INDEX.md`，并从 inbox 删除。
5. 拿不准的留在 inbox，标「待确认」。

## 交接与记忆的关系

交接文档里的「决策」和「未决问题」如果值得长期保留，同步写进对应的记忆文件；不要把整份交接塞进长期记忆。

## 隐私边界

- 记忆不进 git 仓库：仓库只带 `memory.template/`。
- 安装脚本只在 memory 不存在时复制模板，绝不覆盖已有记忆。
- 不写真实姓名、学校、单位、成绩、薪资、住址、session id、API key。
- 需要引用敏感信息时，写「见本地文件」而不是复制内容。

## 示例

```md
## 2026-01-03 检索：广度派子智能体，落盘传路径

- 决策：AGENTS.md 增加检索规则，约束查 Google/GitHub 的行为。
- 原因：摘要会丢细节，全文会撑上下文；落盘传路径两头都不伤。
- 边界：只用于子任务独立、只读、需广撒网的场景。
- 未验证：实际省钱幅度。
```
