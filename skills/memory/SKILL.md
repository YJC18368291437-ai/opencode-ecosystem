长期记忆是给下一个会话看的，不是聊天记录。只写以后还会用到的东西。

## 什么时候写

- 用户说「以后都」「记住」「别再」「这个项目的约定是」
- 做了一个会影响后续方向的决策
- 踩了一个以后还会踩的坑，并找到了修法
- 发现用户稳定的偏好（语言、工具、风格、禁忌）

不要写：一次性的任务细节、临时命令输出、密钥、token、密码、隐私数据。

## 写到哪

| 内容 | 文件 |
|---|---|
| 用户偏好、语言、禁忌 | `~/.config/opencode/memory/preferences.md` |
| 可复用的踩坑与修复 | `~/.config/opencode/memory/lessons.md` |
| 项目特定事实、命令、架构 | `~/.config/opencode/memory/projects/<project>.md` |
| 影响后续方向的决策 | `~/.config/opencode/memory/decisions/<YYYY-MM>.md` |
| 拿不准 | `~/.config/opencode/memory/inbox.md` |

不确定项目名时，用当前目录名的小写短横线形式；没有项目就用 `inbox.md`。

## 怎么写

1. 先读目标文件，避免重复。
2. 一条一个事实，一行说完；需要解释就缩进一行。
3. 有日期就写日期；有来源会话就写 `source: sess_...`。
4. 写不确定性：`（未验证）`、`（待确认）`。
5. 写完更新 `INDEX.md`：主题 | 文件 | 一句话 | 何时用。
6. `INDEX.md` 不超过 50 行；文件不超过 200 行。超了先合并或归档到 `archive/`。

## 整理待整理区

运行 `/memory-tidy` 时：

1. 读 `inbox.md`。
2. 给每条一个建议目标文件和一句摘要。
3. 用表格给用户确认；不要静默移动。
4. 确认后移动、去重、更新 `INDEX.md`，并从 inbox 删除。
5. 拿不准的留在 inbox，标 `（待确认）`。

## 交接时

交接文档里的「决策」和「未决问题」如果值得长期保留，同步写进对应的记忆文件；不要把所有交接内容都塞进长期记忆。
